# SEO audit and implementation plan

**Site:** psova.cz — Czech private psychologist / therapist / coach in Ostrava  
**Audit date:** 2026-08-14  
**Scope:** repository inspection plus current Google Search Central, Schema.org, and Google Business Profile guidance. No application code changed.

## Executive priorities

1. **Fix incorrect prerendered titles before anything else.** The current production build shifts titles between routes: `act-terapie.html` is `test - PSOVA`, `cenik.html` is `ACT Terapie - PSOVA`, and the pattern continues; `values-worksheet.html` has no title. This appears to come from the shared `titleStore` (`src/routes/(content)/store.ts`) being mutated by pages during prerendering and consumed in `src/routes/(content)/+layout.svelte`. Every indexable page should have a descriptive, concise, page-specific `<title>`; Google can rewrite weak or inconsistent titles from headings and other signals ([Google: title links](https://developers.google.com/search/docs/appearance/title-link)). Replace shared mutable metadata with route-local/static page data and verify every generated HTML file.
2. **Give every indexable route unique Czech metadata.** The same site-wide description from `src/app.html` currently appears on all routes. Google recommends accurate page-specific descriptions for important pages, although it may choose visible page text instead and specifies no fixed character limit ([Google: snippets and meta descriptions](https://developers.google.com/search/docs/appearance/snippet)). Add page-specific description, canonical URL, Open Graph title/description/image, and one clear H1 aligned with the page intent.
3. **Add discovery and consolidation basics:** canonical host redirects, self-referencing absolute canonicals, `/robots.txt`, `/sitemap.xml`, Search Console verification/submission, and correct 404 behavior. These are detailed below.
4. **Strengthen health/YMYL trust and local entity consistency:** make qualifications, scope of practice, authorship, contact/location, pricing, privacy, and crisis boundaries easy to verify; align the same real-world name/address/phone/services across the site and Business Profile.
5. **Measure rather than guess:** Search Console queries/pages, indexing and Core Web Vitals; Business Profile performance; genuine enquiry conversions. Use those data to decide which Czech questions deserve content.

## Requirements / technical eligibility (P0)

These are minimum or correctness requirements, not ranking guarantees.

- Googlebot must not be blocked, intended pages must return HTTP `200`, and pages must contain indexable content; meeting these conditions still does **not** guarantee indexing ([Google technical requirements](https://developers.google.com/search/docs/essentials/technical)). Test `/`, every service URL, `/o-mne`, `/cenik`, `/kontakt`, and a nonexistent URL in Search Console URL Inspection and with HTTP checks.
- Ensure nonexistent routes return a real `404`, not a `200` with an error message. Meaningful status codes help Google process JavaScript sites and avoid soft 404s ([Google: JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics#use-meaningful-http-status-codes)).
- Do not block required JS/CSS. Confirm that the rendered HTML in URL Inspection contains the same primary text, links, metadata and structured data users see ([Google: JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)).
- Choose one canonical origin (for example `https://psova.cz/`), permanently redirect HTTP and the alternate `www`/non-`www` host, use one stable trailing-slash policy, link internally to that form, and emit an absolute self-referencing canonical. Redirects and `rel="canonical"` are strong canonical signals; sitemap inclusion is weaker, and canonical declarations remain signals rather than commands ([Google: duplicate URL consolidation](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)).
- Publish a UTF-8 root sitemap containing **only absolute, canonical, indexable URLs**, reference it from `robots.txt`, and submit it in Search Console. A sitemap is a discovery/canonical hint, not an indexing or ranking guarantee; Google ignores sitemap `priority` and `changefreq`, and `lastmod` should reflect a genuine significant update ([Google: build and submit a sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)).
- Use `robots.txt` to manage crawling, not to hide pages. A blocked URL can still appear in Search; for exclusion, allow crawling and use `noindex`, or require authentication for private material ([Google: robots.txt](https://developers.google.com/search/docs/crawling-indexing/robots/intro)).

## On-page and Czech local-intent plan (P1)

### Page map

Keep one substantial page per real user need and service actually offered:

- `/`: who, adult audience, core services, Ostrava location, clear booking path.
- `/poradenstvi`: `Psychologické poradenství pro dospělé v Ostravě | PSOVA`.
- `/hlubinna-psychoterapie`: precise service wording plus who it suits, process, limits, location/online availability.
- `/act-terapie`: ACT explanation, practitioner training, who it may help, process, limits.
- `/koucink`: clearly distinguish coaching from psychological/therapeutic care.
- `/cenik`: prices, duration, cancellation, payment and insurance status.
- `/kontakt`: `Kontakt a psychologická poradna Ostrava | PSOVA`, full address/access/transport/appointment hours and consistent contact details.
- `/o-mne`: practitioner name, role wording, qualifications, memberships, experience, supervision and accurate current training status.

Titles should be unique, concise and descriptive; avoid repeated keyword variants and excessive boilerplate ([Google: title links](https://developers.google.com/search/docs/appearance/title-link#page-titles)). Descriptions should summarize the specific page in natural Czech, not list keywords ([Google: snippets](https://developers.google.com/search/docs/appearance/snippet#meta-descriptions)). There is no Google-prescribed title or description character count; truncation depends on display/device ([titles](https://developers.google.com/search/docs/appearance/title-link#page-titles), [snippets](https://developers.google.com/search/docs/appearance/snippet#meta-descriptions)).

### Content discovery

Use Search Console query data and real client questions to identify useful Czech content (for example what happens at the first session, differences between counselling/therapy/coaching, online versus Ostrava sessions, cancellation, confidentiality and crisis limitations). Publish only where the practitioner can add accurate first-hand expertise. Google favors helpful, original, satisfying people-first content and explicitly says it has no preferred word count ([Google: helpful content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)).

Do **not** create near-duplicate pages for every Ostrava district, nearby town, spelling variant, or “psycholog/terapeut/kouč + location” permutation that all lead to the same practice. Google treats substantially similar region/city funnel pages as potential doorway abuse and unnatural repeated terms as keyword stuffing ([Google spam policies](https://developers.google.com/search/docs/essentials/spam-policies#doorway-abuse)). Location terms should appear where they help a person understand the actual service and place.

## Healthcare/YMYL trust (P1)

Psychological guidance can materially affect health/well-being. Google says its systems give stronger weight to signals aligned with strong E-E-A-T for YMYL topics; trust is most important, but **E-E-A-T is not one specific ranking factor** ([Google: helpful content and E-E-A-T](https://developers.google.com/search/docs/fundamentals/creating-helpful-content#get-to-know-e-e-a-t-and-the-quality-rater-guidelines)). Therefore:

- Clearly name the practitioner and link health/therapy articles to `/o-mne`; add bylines and accurate reviewed/updated dates where readers expect them. Google strongly encourages accurate authorship and evidence of creator background ([Google: “Who, How, Why”](https://developers.google.com/search/docs/fundamentals/creating-helpful-content#who-how-why)).
- Keep verifiable degrees, training, memberships, experience and supervision prominent, while accurately stating limits: the repository says she is **not a clinical psychologist** and the private practice is not insurance-funded healthcare. Do not broaden titles or schema beyond lawful, factual status.
- Source substantive clinical claims to primary clinical/professional material and distinguish educational information from individual advice. Google asks whether content demonstrates expertise, sourcing, author background and factual accuracy; these are quality questions, not mandatory metadata fields ([Google: expertise questions](https://developers.google.com/search/docs/fundamentals/creating-helpful-content#expertise-questions)).
- Make privacy/GDPR, terms/cancellation, price, contact identity/IČ, what a first meeting entails, confidentiality boundaries, and complaint/contact routes easy to find. Add a professionally reviewed statement that the practice is not an emergency service and point urgent visitors to appropriate Czech crisis/emergency resources.
- Review clinical pages when facts or practitioner status materially change. Do not change dates merely to appear fresh; Google explicitly discourages artificial freshness ([Google: search-engine-first warning signs](https://developers.google.com/search/docs/fundamentals/creating-helpful-content#avoid-creating-search-engine-first-content)).

The trust actions above are practical quality recommendations, **not a checklist that guarantees ranking**.

## Local SEO / Google Business Profile (P1)

1. Claim and verify the eligible profile. Keep complete, accurate address, hours, category, phone, website, attributes and photos. Google states local results are mainly based on **relevance, distance and prominence**; complete information helps matching, reviews/ratings and links can contribute to prominence, and there is no way to request or pay for better organic local ranking ([Google Business Profile: local ranking](https://support.google.com/business/answer/7091)).
2. Use the exact real-world practice/practitioner name—do not append “psycholog Ostrava”, services or slogans unless genuinely part of the established name. Choose the fewest categories needed to describe the core business and keep one profile per business ([Google Business Profile representation guidelines](https://support.google.com/business/answer/3038177)). Verify the most specific currently available Czech category in the live profile UI; category labels vary and should not be guessed from English documentation.
3. Because this is an individual practitioner, apply Google's practitioner rules: a public-facing practitioner who can be contacted directly at the verified location during stated hours may have a profile; do not create one per specialization. Avoid duplicates between practitioner and organization profiles unless the official eligibility conditions genuinely support both ([Google Business Profile practitioner guidance](https://support.google.com/business/answer/3038177#individual_practitioners)).
4. Request reviews neutrally from genuine clients only where professionally and ethically appropriate; never incentivize them. Respond helpfully but, because this is therapy, do not confirm a reviewer is/was a client or disclose sensitive details. Google allows review requests without incentives and prohibits incentives for posting/changing/removing reviews ([Google Business Profile: reviews](https://support.google.com/business/answer/3474122)); its profile rules prohibit solicitation of private/confidential information ([representation guidelines](https://support.google.com/business/answer/3038177#content)). The confidentiality wording is a privacy safeguard, not a claimed ranking factor.
5. Maintain consistency between visible site information, JSON-LD and the profile. Add current practice/interior photos and monitor profile edits, duplicate listings, calls, website clicks and direction requests.

## Structured data (P2 opportunity, not a shortcut)

Google supports `LocalBusiness` markup to describe a physical business and recommends the most specific **accurate** subtype, required properties, guideline compliance and validation; valid markup only creates eligibility and does not guarantee a rich result ([Google: LocalBusiness structured data](https://developers.google.com/search/docs/appearance/structured-data/local-business)).

Recommended conservative JSON-LD graph on the home/contact context:

- A stable `@id` for the practice typed **`LocalBusiness`**, with truthful visible `name`, `url`, `image`, `telephone`, `email`, `priceRange`, `address` (`PostalAddress`), `geo` only if verified, appointment/opening hours only if accurate, and `sameAs` only for official profiles. Schema.org defines `LocalBusiness` as a particular physical business, including a medical practice ([Schema.org: LocalBusiness](https://schema.org/LocalBusiness)).
- A linked `Person` for Mgr. Kristýna Sznapková with name, image, URL, accurate `jobTitle`, selected verifiable affiliations/credentials, languages and official same-identity profiles. Those properties are defined for `Person` ([Schema.org: Person](https://schema.org/Person)). Keep detailed qualification evidence visible on `/o-mne`; markup must not make stronger claims than the page.
- Optionally model genuine service pages as `Service` with `name`, `serviceType`, `provider`, `areaServed` and URL; Schema.org defines these properties ([Schema.org: Service](https://schema.org/Service)). Google does not document a special `Service` rich result, so this is semantic clarity, not an expected SERP enhancement.

**Type decision:** do not use deprecated `ProfessionalService`; Schema.org says it was deprecated because of confusion with `Service` ([Schema.org: ProfessionalService](https://schema.org/ProfessionalService)). Do not use `Physician` (defined as a physician/physician office) or `MedicalClinic` unless the legal and operational facts change ([Schema.org: Physician](https://schema.org/Physician), [MedicalClinic](https://schema.org/MedicalClinic)). `MedicalBusiness` is defined as a business for medical purposes run by health professionals ([Schema.org: MedicalBusiness](https://schema.org/MedicalBusiness)), but the site's own explicit non-clinical/non-healthcare positioning makes plain `LocalBusiness` the safer truthful choice pending Czech professional/legal confirmation. `PsychologicalTreatment` describes the treatment process, not the practitioner/business ([Schema.org: PsychologicalTreatment](https://schema.org/PsychologicalTreatment)).

Validate syntax with [Schema.org Validator](https://validator.schema.org/) and Google eligibility with the [Rich Results Test](https://search.google.com/test/rich-results), then inspect the rendered result in Search Console. Do not copy Google reviews into `Review`/`AggregateRating` markup to seek stars: Google excludes self-serving reviews about the marked-up `LocalBusiness`/`Organization` from review-star display ([Google: self-serving review rich results](https://developers.google.com/search/blog/2019/09/making-review-rich-results-more-helpful)).

## Performance and measurement (P2, ongoing)

- Target good field Core Web Vitals: LCP within 2.5 s, INP under 200 ms, CLS under 0.1. Google recommends these for user experience and says page experience aligns with what core ranking systems seek to reward; passing them is not a ranking guarantee ([Google: Core Web Vitals](https://developers.google.com/search/docs/appearance/core-web-vitals)). Measure the 75th-percentile field data in Search Console/CrUX, then use lab tooling to diagnose templates.
- Prioritize the portrait/hero LCP image, explicit image dimensions/aspect ratios, responsive appropriately compressed office/portrait images, font loading, and minimal client JavaScript. Re-test home, service and contact templates on mobile.
- In Search Console monitor sitemap processing, Page Indexing, Core Web Vitals, manual actions, query/page/country/device performance and representative URL Inspection. Compare branded (`PSOVA`, practitioner name) and non-branded local/service discovery; connect enquiries without collecting unnecessary sensitive health data.
- Quarterly: inspect Business Profile accuracy/performance and Search Console; every 6–12 months: review titles, stale facts, credentials, service scope, broken links, structured data and crisis information. Change content when it helps users, not on an arbitrary “freshness” schedule ([Google: helpful content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)).

## Explicitly unsupported / uncertain tactics

- **No guaranteed ranking from schema, sitemap, metadata length, Core Web Vitals, or an “E-E-A-T score.”** Google explicitly does not guarantee indexing or rich results, and E-E-A-T is not one standalone factor ([technical requirements](https://developers.google.com/search/docs/essentials/technical), [structured data](https://developers.google.com/search/docs/appearance/structured-data/local-business), [E-E-A-T](https://developers.google.com/search/docs/fundamentals/creating-helpful-content#get-to-know-e-e-a-t-and-the-quality-rater-guidelines)).
- **No preferred word count** and no need to publish frequently merely to appear fresh ([Google: helpful content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content#avoid-creating-search-engine-first-content)).
- **No keyword-stuffed Business Profile name, fake location pages, duplicate profiles, bought/incentivized reviews, or review-star schema workaround.** These conflict with the official policies cited above.
- Search volume, competitor gaps and exact Czech Business Profile categories cannot be established from these primary documentation sources alone. Use first-party Search Console/Profile data and the live category picker; treat third-party keyword-volume numbers as estimates, not Google requirements.
- `meta keywords`, domain-name keyword tricks, keyword density targets, mass directory submissions and exact-match anchor campaigns have no support in the reviewed official guidance. Do not prioritize them over accurate content, crawlability, local profile quality and real-world reputation.

## Suggested delivery sequence

- **Week 1 / P0:** repair title architecture and worksheet index decision; unique descriptions; canonical host/URL policy; 404 checks; robots and sitemap; Search Console submission and URL inspections.
- **Weeks 2–3 / P1:** rewrite titles/H1s/snippets around actual page intent; improve home/contact/service differentiation; expose verified qualifications, scope, privacy and crisis boundaries; audit and align Business Profile.
- **Weeks 3–4 / P2:** add validated conservative JSON-LD; image/font/CWV work; conversion and Search Console measurement.
- **Monthly/quarterly:** use observed queries and enquiries to improve existing pages first, then add only genuinely useful expert content; monitor indexing, profile accuracy, reviews and field performance.
